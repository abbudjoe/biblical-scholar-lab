# Owner merge authorization specification

## GOV-01-S03 active rule

Joseph's exact-head approval in the current ChatGPT conversation is the human gate. No `OwnerMergeAuthorizationRecord`, owner-record schema check, or owner-record PR comment is an active prerequisite.

The separate merge-only prompt must name the repository, PR, exact head, clean-review identity, and Joseph approval reference. Merge-only Sol verifies the unchanged head, activation-named task-specific checks, and conversations before using `--match-head-commit`. A new commit invalidates review and approval.

## Historical pre-S03 specification — non-authoritative

## Purpose

Joseph and Codex share the GitHub login `@abbudjoe` and the existing authenticated `gh` credential. GitHub account identity therefore cannot independently prove that an action was performed personally by Joseph.

Human merge approval is represented by Joseph's explicit approval of an exact PR head in the current ChatGPT conversation, followed by a separate merge-only prompt generated by ChatGPT and sent by Joseph to Sol.

The implementation root-turn prompt is never merge authority.

## Preconditions

ChatGPT may produce a merge-only authorization prompt only when:

- The PR is open and targets `main`.
- The activation is approved.
- `project-integrity` passes on the current head.
- `turn-handoff-integrity` passes on the current head.
- `chatgpt-review-integrity` passes on the current head.
- ChatGPT's disposition is `CHATGPT_REVIEW_CLEAN`.
- No unresolved conversation or blocking failure remains.
- Joseph explicitly approves the exact PR head.

## Human action

Joseph's approval must identify or unambiguously inherit:

```text
repository
PR URL or number
exact PR-head SHA
ChatGPT review ID
merge method: squash
```

ChatGPT then generates a separate merge-only prompt containing one schema-valid `OwnerMergeAuthorizationRecord`.

Joseph sends that prompt to Sol only when he intends that exact head to be merged.

## Record

The record contains:

```text
authorization_id
repository
pr_url
activation_id
chatgpt_review_id
authorized_head_sha
owner_login
authorization_channel
owner_approval_reference
approved_at
merge_method
status
```

The merge-only Sol turn posts the record as a machine-readable PR comment. It is not committed to the PR branch because doing so would change the authorized head.

The trusted `owner-merge-record-integrity` check validates exact-head consistency and schema. It does not independently authenticate that the GitHub actor was physically Joseph.

## Invalidation

Authorization is invalid when:

- The PR head changes.
- The activation changes.
- The ChatGPT review is superseded or no longer clean.
- A required check becomes nonpassing.
- The PR closes or retargets.
- Joseph withdraws or supersedes approval.
- The authorization has already been used.

## Merge-only execution

The merge-only Sol turn must:

1. Verify the live head equals `authorized_head_sha`.
2. Verify the referenced ChatGPT review remains current and clean.
3. Post the authorization record as a PR comment.
4. Wait for `owner-merge-record-integrity` to pass.
5. Verify every required check and conversation is clear.
6. Mark the PR ready if necessary.
7. Execute exactly:

```bash
gh pr merge <PR> --squash --match-head-commit <AUTHORIZED_HEAD_SHA> --delete-branch
```

8. Verify the resulting `main` commit and post-merge checks.
9. Post a merge receipt and stop.

It may not use `--admin`, `--auto`, bypass, update, rebase, force-push, modify workflows, alter authorization, change code, or begin another task.

If the merge-only process cannot be implemented faithfully, Joseph performs the merge personally.
