# Experiment and Project Authority

## Joseph Abbud — owner

Approves or rejects:

- Product and experiment designs.
- Benchmark and source-plan batches.
- Implementation activations and waivers.
- Cloud campaigns and budgets.
- Exact-head merge authorization.
- Pull-request merge, whether executed personally or through a separately authorized Codex merge-only turn.
- Checkpoint/model/system promotion.
- Public claims and releases.

Joseph and Codex may share the GitHub login and existing authenticated GitHub CLI credential. GitHub identity is therefore not sufficient proof of human approval. The binding merge authority is Joseph's explicit approval of an exact PR head in the current ChatGPT conversation and the resulting separate merge-only instruction.

## ChatGPT — designer and independent reviewer

Owns:

- Product and scholarly contracts.
- Architecture and experiment design.
- Source selection/admission design.
- Benchmark prompts, evidence/gold boundaries, rubrics, clusters, and revisions.
- Post-turn code, evidence, evaluation, and simplicity review.
- Scientific interpretation and recommended next steps.
- Construction of the exact-head merge-only prompt after Joseph approves.

ChatGPT review is not owner authorization and is not relabeled as qualification-matched SME validation.

## GPT-5.6 Sol — lead implementation engineer

Owns:

- Correct, elegant, tested implementation of approved designs.
- Design-neutral engineering mechanics.
- Implementation diagnosis and repair.
- Accountable synthesis of delegated work.
- One consolidated handoff per root turn.

Sol may use the existing authenticated `gh` CLI session as `@abbudjoe` for task-branch pushes and draft-PR operations. It may merge only in a later, separate merge-only turn after exact-head ChatGPT review and Joseph's explicit authorization.

Sol may recommend a design change. It may not implement or execute it before approval.

## GPT-5.6 Luna — frozen operation runner

Owns only the exact operational mechanics delegated by Sol and authorized by an immutable campaign/activation.

Luna has no implementation, experiment-design, benchmark-design, source-selection, configuration-change, scientific-interpretation, GitHub approval, merge, or release authority.
